## 2. Deskripsi Praktikum

Sistem operasi server merupakan komponen utama yang mengelola sumber daya komputasi dan menyediakan lingkungan bagi layanan yang dibutuhkan oleh pengguna. Administrator sistem harus mampu melakukan instalasi, konfigurasi awal, serta verifikasi sistem operasi agar server dapat beroperasi secara stabil dan siap dikembangkan untuk menyediakan berbagai layanan.

Pada praktikum ini, mahasiswa melakukan pembuatan mesin virtual, instalasi sistem operasi server berbasis Linux, konfigurasi identitas server, pengaturan jaringan, pembaruan paket, pengelolaan akun administratif, serta konfigurasi akses jarak jauh menggunakan Secure Shell (SSH).

Mahasiswa diharapkan tidak hanya berhasil menginstal sistem operasi, tetapi juga mampu menjelaskan alasan setiap konfigurasi, melakukan pengujian, dan mendokumentasikan hasil implementasi.

## 3. Capaian Pembelajaran Praktikum

Setelah menyelesaikan praktikum, mahasiswa diharapkan mampu:

1. Membuat dan mengonfigurasi mesin virtual untuk kebutuhan server.
2. Menginstal sistem operasi server berbasis Linux sesuai rancangan.
3. Mengonfigurasi hostname, akun administratif, dan parameter jaringan dasar.
4. Melakukan pembaruan sistem serta memeriksa status layanan dan sumber daya.
5. Mengonfigurasi dan menguji akses administratif jarak jauh melalui SSH.
6. Memverifikasi hasil instalasi dan menyusun dokumentasi konfigurasi server.

## 4. Dasar Teori

### 4.1. Sistem Operasi Server

Sistem operasi server merupakan perangkat lunak sistem yang mengelola sumber daya perangkat keras, menjalankan proses, mengatur akses pengguna, dan menyediakan lingkungan untuk layanan jaringan maupun aplikasi.

Berbeda dengan sistem operasi desktop yang umumnya berorientasi pada interaksi pengguna secara langsung, sistem operasi server dirancang untuk mendukung layanan yang berjalan secara berkelanjutan, administrasi jarak jauh, dan pengelolaan sumber daya secara terkontrol.

Contoh sistem operasi server berbasis Linux yang umum digunakan adalah Ubuntu Server dan Debian. Keduanya menyediakan lingkungan administrasi berbasis command-line interface (CLI), pengelolaan paket, sistem layanan, dan mekanisme pengaturan akun serta hak akses.

### 4.2. Virtualisasi Server

Virtualisasi memungkinkan beberapa lingkungan komputasi berjalan secara terisolasi pada satu perangkat keras fisik. Dalam praktikum ini, VirtualBox digunakan untuk membuat mesin virtual (virtual machine atau VM) yang berfungsi sebagai server.

Setiap VM memiliki sumber daya virtual, seperti CPU, RAM, penyimpanan, dan antarmuka jaringan. Alokasi sumber daya harus mempertimbangkan kapasitas komputer fisik agar host dan VM dapat beroperasi secara memadai.

Parameter awal VM yang disarankan adalah:

| Komponen            | Konfigurasi awal                                                       |
| ------------------- | ---------------------------------------------------------------------- |
| Nama VM             | `Ubuntu SysAdmin`                                                      |
| Tipe sistem         | Linux 64-bit, Ubuntu                                                   |
| CPU                 | Minimal 1 vCPU                                                         |
| RAM                 | Minimal 2 GB                                                           |
| Penyimpanan virtual | 25 GB, dinamis atau sesuai kebutuhan                                   |
| Media instalasi     | ISO Ubuntu Server 26.04 LTS                                            |
| Jaringan            | NAT untuk pembaruan awal; jaringan tambahan sesuai kebutuhan pengujian |

Spesifikasi tersebut merupakan rekomendasi untuk praktikum dasar, bukan persyaratan universal. Mahasiswa perlu menyesuaikannya dengan persyaratan versi OS dan kapasitas perangkat.

### 4.3. Identitas Server dan Pengelolaan Akun

Setiap server perlu memiliki identitas yang jelas agar mudah dikenali dalam lingkungan jaringan. Salah satu parameter identitas tersebut adalah hostname, yaitu nama yang digunakan untuk mengidentifikasi sistem.

Selain itu, administrator perlu memahami perbedaan akun pengguna biasa dan akun dengan hak administratif. Pada Ubuntu dan Debian, tugas administratif dapat dilakukan melalui mekanisme `sudo` apabila akun telah diberikan hak yang sesuai.

Prinsip yang perlu diterapkan adalah penggunaan akun individual, pembatasan hak akses berdasarkan kebutuhan, serta penghindaran penggunaan akun administratif untuk aktivitas rutin yang tidak memerlukan hak istimewa.

### 4.4. Konfigurasi Jaringan Server

Konfigurasi jaringan memungkinkan server berkomunikasi dengan perangkat lain. Parameter jaringan yang umum meliputi:

- Alamat IP.
- Subnet mask atau prefix.
- Default gateway.
- DNS resolver.

Alamat IP dapat diperoleh secara dinamis melalui DHCP atau ditetapkan secara statis. Untuk server yang memerlukan alamat tetap, penggunaan IP statis atau reservasi DHCP umumnya mempermudah pengelolaan layanan.

Konfigurasi IP statis dilakukan hanya jika jaringan yang digunakan telah diketahui dan alamat yang ditetapkan tidak bertabrakan dengan perangkat lain.

### 4.5. Manajemen Paket dan Pembaruan Sistem

Distribusi Linux menyediakan pengelola paket untuk menginstal, memperbarui, dan menghapus perangkat lunak. Pada Ubuntu dan Debian, APT digunakan untuk mengelola paket dari repositori yang dikonfigurasi.

Perintah berikut merupakan perintah dasar yang akan digunakan:

| Perintah                      | Fungsi                                  |
| ----------------------------- | --------------------------------------- |
| `sudo apt update`             | Memperbarui indeks paket                |
| `sudo apt upgrade`            | Memasang pembaruan paket yang tersedia  |
| `sudo apt install nama-paket` | Menginstal paket                        |
| `apt list --upgradable`       | Menampilkan paket yang dapat diperbarui |
| `dpkg -l`                     | Menampilkan paket yang terpasang        |

Pembaruan indeks paket tidak sama dengan pembaruan seluruh perangkat lunak. Oleh karena itu, `apt update` biasanya diikuti dengan `apt upgrade` ketika pembaruan memang akan diterapkan.

### 4.6. Secure Shell (SSH)

Secure Shell merupakan protokol yang memungkinkan pengguna mengakses dan mengelola sistem jarak jauh melalui koneksi terenkripsi. Pada server Linux, layanan SSH biasanya disediakan oleh paket OpenSSH Server.

Dengan SSH, administrator dapat menjalankan perintah, memeriksa status sistem, serta mengelola layanan tanpa harus berinteraksi langsung dengan konsol VM.

Pengujian SSH harus dilakukan dari perangkat atau lingkungan klien yang memiliki konektivitas ke server. Keberhasilan SSH bergantung pada beberapa faktor, termasuk status layanan, alamat IP, aturan firewall, dan mode jaringan virtual yang digunakan.

## 6. Keselamatan dan Ketentuan Praktikum

1. Pastikan komputer memiliki kapasitas RAM dan ruang penyimpanan yang memadai sebelum membuat VM.
   - Minimal RAM 8 GB, disarankan 16 GB atau lebih.
   - Minimal penyimpanan 20 GB.
2. Gunakan berkas ISO dari sumber resmi Ubuntu.
3. Jangan mengubah konfigurasi jaringan fisik laboratorium tanpa izin.
4. Gunakan alamat IP yang telah ditetapkan, terutama jika menggunakan mode *Bridged Adapter*.
5. Jangan memasukkan kata sandi atau kredensial pribadi ke dalam laporan praktikum.
6. Simpan konfigurasi dan dokumentasi secara berkala.

### Tahap 3 — Verifikasi instalasi dan identitas server (20 menit)

Setelah berhasil masuk, jalankan perintah berikut satu per satu.

1. Memeriksa hostname

   ```
   hostname
   ```
   atau
   ```
   hostnamectl
   ```

   Hasil yang diharapkan menunjukkan nama host yang sesuai dengan rancangan.

2. Memeriksa versi sistem operasi

   ```
   cat /etc/os-release
   ```

   Catat nama distribusi dan versi yang digunakan.

3. Memeriksa kernel

   ```
   uname -r
   ```

   Perintah tersebut menampilkan versi kernel Linux yang sedang digunakan.

4. Memeriksa sumber daya

   ```
   lscpu
   ```
   ```
   free -h
   ```
   ```
   df -h
   ```

   Gunakan hasilnya untuk memverifikasi jumlah CPU yang terlihat oleh VM, kapasitas memori, dan penggunaan penyimpanan.

5. Memeriksa identitas pengguna

   ```
   whoami
   ```
   ```
   id
   ```

   Perintah tersebut membantu memverifikasi akun yang sedang digunakan serta identitas dan grup pengguna.

### Tahap 4 — Konfigurasi dasar dan pembaruan sistem (25 menit)

1. Memeriksa status jaringan

   ```
   ip -br address
   ```
   ```
   ip route
   ```

   Identifikasi antarmuka jaringan yang aktif, alamat IP, dan default route. Nama antarmuka tidak selalu sama pada setiap VM.

2. Memperbarui indeks paket

   ```
   sudo apt update
   ```

   Periksa apakah repositori dapat diakses dan tidak terdapat kesalahan yang menghalangi pembaruan.

3. Memasang pembaruan yang tersedia

   ```
   sudo apt upgrade
   ```

   Tinjau daftar perubahan sebelum menyetujui proses pembaruan. Jika sistem meminta konfirmasi, lanjutkan sesuai instruksi yang ditampilkan (biasanya dengan menekan <kbd>y</kbd> lalu <kbd>Enter</kbd>).

4. Memasang utilitas pendukung

   ```
   sudo apt install openssh-server curl
   ```

   Perintah ini akan memasang paket Open SSH Server dan Curl. Jika paket sudah terpasang, APT akan menyesuaikan tindakannya berdasarkan keadaan sistem.

5. Memeriksa waktu sistem

   ```
   timedatectl
   ```

   Catat informasi waktu dan zona waktu. Jika zona waktu salah, sesuaikan zona waktu dengan lokasi sekarang.

   ```
   timedatectl list-timezones
   ```
   ```
   sudo timedatectl set-timezone Region/City
   ```
   Contoh:
   ```
   sudo timedatectl set-timezone Asia/Taipei
   ```

6. Memeriksa status layanan SSH

   ```
   sudo systemctl status ssh
   ```

   Pada Ubuntu Server dan Debian, unit layanan umumnya bernama `ssh`. Jika layanan belum aktif, jalankan:

   ```
   sudo systemctl enable --now ssh
   ```

Kemudian periksa kembali statusnya. Jika terjadi kegagalan, analisis pesan kesalahan sebelum melakukan perubahan lebih lanjut.

### Tahap 5 — Konfigurasi dan verifikasi SSH (25 menit)

SSH digunakan untuk mengelola server dari perangkat klien. Sebelum menguji koneksi, pastikan layanan SSH aktif dan alamat IP server dapat dijangkau dari klien (lakukan uji koneksi dengan ping).

1. Memahami keterbatasan mode NAT

   Pada VirtualBox, VM dengan mode NAT umumnya dapat memulai koneksi keluar, tetapi tidak otomatis menerima koneksi masuk dari jaringan host atau klien lain. Untuk menguji SSH dari host, mahasiswa dapat menggunakan port forwarding dengan pemetaan port host ke port 22 VM, atau menggunakan mode jaringan lain seperti *Bridged* atau *Host-only Adapter*.

   Contoh pemetaan port host `2222` ke port VM `22`:

   - Host IP: `127.0.0.1`
   - Host Port: `2222`
   - Guest Port: `22`

   Koneksi dari host kemudian dapat diuji menggunakan:

   ```
   ssh -p 2222 nama_pengguna@127.0.0.1
   ```

   :::tip
   Cara yang lebih mudah adalah dengan menggunakan dual-adapter. Matikan VM, kemudian aktifkan Adapter 2 di pengaturan jaringan VirtualBox, lalu pilih Bridged Adapter atau Host-only Adapter sebagai koneksi di Adapter 2 (biarkan Adapter 1 tetap NAT). Dengan demikian, VM dapat terhubung ke Internet melalui Adapter 1, dan host dapat langsung terhubung ke VM melalui Adapter 2.
   **Tidak perlu melakukan port-forwarding lagi jika sudah menggunakan dual-adapter.**
   :::

2. Memeriksa alamat IP server

   ```
   ip -br address
   ```

   Catat alamat IP pada antarmuka yang digunakan untuk komunikasi dengan klien.

3. Memeriksa port SSH

   ```
   sudo ss -lntp
   ```

   Cari proses yang mendengarkan pada port TCP 22 atau port SSH lain yang telah dikonfigurasi.

4. Menguji dari komputer klien

   Jika klien memiliki aplikasi SSH dan dapat menjangkau alamat IP server, jalankan:

   ```
   ssh nama_pengguna@alamat_ip_server
   ```

   Ganti `nama_pengguna` dan `alamat_ip_server` dengan nilai aktual. Pada koneksi pertama, verifikasi identitas host sebelum menerima kunci host. Setelah itu, autentikasi menggunakan akun yang telah dibuat. Contoh:

   ```
   ssh sysadmin@192.168.0.100
   ```

5. Memverifikasi akses

   Setelah koneksi berhasil, jalankan:

   ```
   hostname
   ```
   ```
   whoami
   ```
   ```
   uptime
   ```

   Hasilnya harus menunjukkan identitas server dan pengguna yang sesuai.

### Tahap 6 — Dokumentasi dan pemeriksaan akhir (15 menit)

Lakukan pemeriksaan akhir dengan menjalankan perintah berikut (sebaiknya dijalankan per baris agar lebih mudah dibaca).

```
hostnamectl
cat /etc/os-release
ip -br address
ip route
free -h
df -h
systemctl is-active ssh
```

Masukkan hasil pemeriksaan ke tabel berikut.

| Parameter             | Hasil yang diharapkan           | Hasil aktual | Status |
| --------------------- | ------------------------------- | ------------ | ------ |
| Sistem operasi        | Sesuai rancangan                |              |        |
| Hostname              | `sysadmin`                      |              |        |
| CPU dan RAM           | Sesuai alokasi VM               |              |        |
| Alamat IP             | Sesuai skema jaringan           |              |        |
| Konektivitas jaringan | Sesuai mode jaringan            |              |        |

Isi kolom status dengan berhasil, belum berhasil, atau perlu perbaikan. Jika suatu pengujian gagal, dokumentasikan pesan kesalahan dan tindakan korektif yang telah dilakukan.

## 8. Tugas Praktikum

Mahasiswa diminta menyelesaikan tugas berikut berdasarkan hasil implementasi.

### Tugas 1. Instalasi sistem operasi server

Lakukan instalasi Ubuntu Server 26.04 LTS atau Debian pada VirtualBox.

Dokumentasikan:

1. Nama dan versi sistem operasi.
2. Spesifikasi mesin virtual.
3. Tahapan utama instalasi.
4. Konfigurasi identitas server.
5. Kendala yang ditemukan selama instalasi, jika ada.

### Tugas 2. Konfigurasi dan verifikasi sistem

Lakukan konfigurasi dasar sistem operasi, kemudian verifikasi hasilnya menggunakan perintah Linux yang telah dipraktikkan.

Mahasiswa harus menyertakan hasil pemeriksaan hostname, versi OS, kernel, CPU, RAM, penyimpanan, dan konfigurasi jaringan.

### Tugas 3. Pembaruan sistem dan pengelolaan layanan SSH

Lakukan pembaruan indeks paket dan pembaruan sistem. Pastikan layanan SSH terpasang dan berjalan, kemudian lakukan pengujian koneksi dari klien atau melalui port forwarding apabila menggunakan NAT.

Jika koneksi tidak berhasil, identifikasi penyebabnya berdasarkan status layanan, alamat IP, mode jaringan, dan pesan kesalahan yang diperoleh.

## 9. Pertanyaan Analisis

9. Mengapa hasil instalasi dan konfigurasi harus didokumentasikan sebelum server digunakan untuk menyediakan layanan produksi?

Hasil praktikum ini menjadi fondasi bagi Pertemuan 2: Konfigurasi User, Permission, dan Sumber Daya Berbagi Pakai. Setelah menyelesaikan seluruh tahap praktikum 1, **buat dan simpan Snapshot VM dengan nama `praktikum 1`**. Dengan demikian, mahasiswa membangun satu lingkungan server secara bertahap, mulai dari instalasi OS, pengelolaan akun, penyediaan layanan, pengamanan, monitoring, hingga backup dan pemulihan.

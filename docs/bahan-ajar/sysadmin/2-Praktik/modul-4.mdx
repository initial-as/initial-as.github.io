## 5. Dasar Teori

### 5.1. Application Services

Application services merupakan layanan yang disediakan oleh server untuk menjalankan atau menyediakan aplikasi yang dapat digunakan oleh komputer klien melalui jaringan. Dalam lingkungan server, application services memungkinkan pengguna mengakses berbagai aplikasi tanpa harus menjalankan seluruh proses aplikasi pada perangkat masing-masing. Contoh application services antara lain:

1. Web server.
2. Database server.
3. Mail server.
4. File sharing server.
5. Application server.

Pada praktikum ini, mahasiswa akan mengimplementasikan web server sebagai salah satu bentuk application services.

### 5.2. Web Server

Web server merupakan perangkat lunak yang bertugas menerima permintaan dari klien melalui protokol HTTP atau HTTPS dan mengirimkan respons berupa halaman web maupun sumber daya lainnya. Proses komunikasi antara klien dan web server secara umum berlangsung sebagai berikut:

1. Pengguna memasukkan alamat website pada browser.
2. Browser memperoleh alamat IP server melalui proses DNS resolution.
3. Browser mengirimkan HTTP request ke server.
4. Web server memproses permintaan tersebut.
5. Web server mengirimkan HTTP response kepada klien.
6. Browser menampilkan halaman website kepada pengguna.

Web server umumnya menggunakan port berikut:

| Protokol | Port Default | Fungsi                             |
| -------- | ------------ | ---------------------------------- |
| HTTP     | 80           | Komunikasi web tanpa enkripsi      |
| HTTPS    | 443          | Komunikasi web dengan enkripsi TLS |

### 5.3. Apache Web Server

Apache HTTP Server merupakan perangkat lunak web server yang bersifat open source dan banyak digunakan untuk menyediakan layanan website. Apache mendukung berbagai fitur, antara lain:

1. Menyediakan halaman web melalui protokol HTTP.
2. Mengelola beberapa website menggunakan virtual hosting.
3. Mengatur akses terhadap direktori website.
4. Mendukung modul tambahan untuk memperluas fungsionalitas.
5. Mengelola konfigurasi website secara terpisah.

Pada Ubuntu Server dan Debian, Apache dapat diinstalasi melalui package manager:

```
sudo apt install apache2
```

Beberapa direktori dan berkas penting Apache adalah:

| Direktori/Berkas                | Fungsi                                   |
| ------------------------------- | ---------------------------------------- |
| `/etc/apache2/`                 | Direktori konfigurasi Apache             |
| `/etc/apache2/sites-available/` | Konfigurasi virtual host yang tersedia   |
| `/etc/apache2/sites-enabled/`   | Konfigurasi virtual host yang diaktifkan |
| `/var/www/html/`                | Direktori default website                |
| `/var/log/apache2/access.log`   | Catatan permintaan yang diterima server  |
| `/var/log/apache2/error.log`    | Catatan kesalahan layanan Apache         |

### 5.4. Virtual Hosting

Virtual hosting merupakan teknik yang memungkinkan satu web server melayani beberapa website menggunakan satu alamat IP atau satu server. Dengan virtual hosting, administrator dapat mengelola beberapa website tanpa harus menyediakan satu server fisik atau virtual untuk setiap website. Terdapat beberapa jenis virtual hosting:

1. **Name-based virtual hosting:** beberapa website menggunakan alamat IP yang sama, tetapi dibedakan berdasarkan nama domain atau hostname.
2. **IP-based virtual hosting:** setiap website menggunakan alamat IP yang berbeda.
3. **Port-based virtual hosting:** website dibedakan berdasarkan nomor port yang digunakan.

Pada praktikum ini, mahasiswa akan menggunakan *name-based virtual hosting*. Sebagai contoh, satu server dengan alamat IP `192.168.56.10` dapat melayani dua website:

| Nama Domain       | Alamat IP     |
| ----------------- | ------------- |
| `web.pti.test`    | 192.168.56.10 |
| `portal.pti.test` | 192.168.56.10 |

Apache akan menentukan website yang harus ditampilkan berdasarkan informasi hostname pada HTTP request yang diterima.

### 5.5. Apache Virtual Host Configuration

Konfigurasi virtual host Apache pada Ubuntu Server atau Debian umumnya disimpan pada direktori:

```
/etc/apache2/sites-available/
```

Setiap website dapat memiliki berkas konfigurasi tersendiri.

Contoh konfigurasi virtual host:

```
<VirtualHost *:80>
    ServerName web.pti.test
    DocumentRoot /var/www/web.pti.test/public_html

    ErrorLog ${APACHE_LOG_DIR}/web-error.log
    CustomLog ${APACHE_LOG_DIR}/web-access.log combined
</VirtualHost>
```

Beberapa parameter penting dalam konfigurasi tersebut adalah:

| Parameter      | Fungsi                                                 |
| -------------- | ------------------------------------------------------ |
| `VirtualHost`  | Menentukan alamat dan port yang digunakan virtual host |
| `ServerName`   | Menentukan nama domain website                         |
| `DocumentRoot` | Menentukan direktori utama berkas website              |
| `ErrorLog`     | Menentukan lokasi log kesalahan website                |
| `CustomLog`    | Menentukan lokasi log aktivitas akses website          |

Apache menyediakan perintah untuk mengaktifkan dan menonaktifkan konfigurasi virtual host:

```
sudo a2ensite nama-konfigurasi.conf
```

Untuk menonaktifkan virtual host:

```
sudo a2dissite nama-konfigurasi.conf
```

### 5.6. Integrasi DNS dan Web Server

Web server dapat diakses melalui nama domain apabila DNS telah dikonfigurasi untuk mengarahkan nama domain tersebut ke alamat IP server.

Dalam praktikum sebelumnya, mahasiswa telah membuat DNS server lokal menggunakan BIND9. Layanan tersebut akan digunakan untuk mengarahkan nama domain website ke alamat IP server.

Sebagai contoh:

```
web.pti.test    A    192.168.56.10
```

Dengan konfigurasi tersebut, klien dapat mengakses website melalui alamat:

```
http://web.pti.test
```

DNS bertugas menerjemahkan nama domain menjadi alamat IP, sedangkan Apache bertugas menentukan dan menyajikan konten website berdasarkan nama domain yang diminta klien.

### 5.7. Nginx sebagai Alternatif Web Server

Selain Apache, terdapat perangkat lunak web server lain yang banyak digunakan, yaitu Nginx. Nginx merupakan web server yang juga mendukung virtual hosting dan dapat digunakan sebagai alternatif Apache. Beberapa perbedaan umum antara Apache dan Nginx adalah:

| Aspek                    | Apache                                 | Nginx                                         |
| ------------------------ | -------------------------------------- | --------------------------------------------- |
| Konfigurasi virtual host | VirtualHost                            | Server block                                  |
| Direktori konfigurasi    | `/etc/apache2/`                        | `/etc/nginx/`                                 |
| Pengelolaan website      | `a2ensite` dan `a2dissite`             | Symlink konfigurasi                           |
| Model pemrosesan         | Multi-Processing Modules (MPM)         | Event-driven architecture                     |
| Penggunaan               | Web server dan application integration | Web server, reverse proxy, dan load balancing |

Pada praktikum ini, Apache digunakan sebagai implementasi utama. Nginx dapat digunakan sebagai alternatif web server atau pun dikombinasikan sebagai reverse proxy.

:::info
Apache dan Nginx dapat diinstal pada satu server, tetapi tidak dapat menggunakan alamat IP dan port yang sama secara bersamaan tanpa konfigurasi tambahan. Untuk praktikum ini, gunakan salah satu web server sebagai layanan utama.
:::

### 8.2. Pemeriksaan dan Persiapan DNS (15 menit)

Pada tahap ini, mahasiswa akan memastikan domain website telah diarahkan ke alamat IP server melalui DNS lokal.

1. Memeriksa konfigurasi zona DNS

   Buka berkas konfigurasi zona:

   ```
   sudo nano /etc/bind/db.pti.test
   ```

   Pastikan terdapat record untuk domain website:

   ```
   @       IN  NS  server.pti.test.
   @       IN  A   192.168.56.10
   server  IN  A   192.168.56.10
   web     IN  A   192.168.56.10
   portal  IN  A   192.168.56.10
   ```

   Jika record `web` dan `portal` belum tersedia, tambahkan keduanya.

   Perbarui nomor serial SOA setiap kali melakukan perubahan pada berkas zona.

2. Memeriksa konfigurasi zona DNS

   Jalankan:

   ```
   sudo named-checkconf
   sudo named-checkzone pti.test /etc/bind/db.pti.test
   ```

   Pastikan hasil pemeriksaan menunjukkan status `OK`.

3. Memulai ulang layanan BIND9

   ```
   sudo systemctl restart bind9
   ```

4. Menguji resolusi nama domain

   Jalankan:

   ```
   dig @127.0.0.1 web.pti.test
   dig @127.0.0.1 portal.pti.test
   ```

   Pastikan kedua domain mengarah ke alamat IP:

   ```
   192.168.56.10
   ```

### 8.3. Instalasi Apache Web Server (20 menit)

Pada tahap ini, mahasiswa akan menginstalasi Apache sebagai web server.

1. Memperbarui daftar paket

   ```
   sudo apt update
   ```

2. Menginstal Apache

   ```
   sudo apt install apache2 curl -y
   ```

3. Memeriksa status layanan Apache

   ```
   sudo systemctl status apache2
   ```

4. Mengaktifkan layanan Apache

   ```
   sudo systemctl enable --now apache2
   ```

5. Memeriksa status layanan

   ```
   systemctl is-active apache2
   ```

   Hasil yang diharapkan adalah `active`.

6. Memeriksa port yang digunakan Apache

   Jalankan:

   ```
   sudo ss -lntp | grep ':80'
   ```

   Pastikan Apache telah mendengarkan pada port 80.

### 8.4. Membuat Website Pertama (30 menit)

Pada tahap ini, mahasiswa akan membuat website pertama dengan nama domain `web.pti.test`.

1. Membuat direktori website

   Buat direktori untuk menyimpan berkas website:

   ```
   sudo mkdir -p /var/www/web.pti.test/public_html
   ```

2. Mengatur kepemilikan direktori

   Gunakan akun administrator sebagai pemilik direktori:

   ```
   sudo chown -R root:root /var/www/web.pti.test
   ```

   Atur permission direktori dan berkas:

   ```
   sudo find /var/www/web.pti.test -type d -exec chmod 755 {} \;
   sudo find /var/www/web.pti.test -type f -exec chmod 644 {} \;
   ```

3. Membuat halaman website

   Buat berkas `index.html`:

   ```
   sudo nano /var/www/web.pti.test/public_html/index.html
   ```

   Masukkan kode HTML berikut:

   ```
   <!DOCTYPE html>
   <html lang="id">
   <head>
      <meta charset="UTF-8">
      <meta name="viewport" content="width=device-width, initial-scale=1.0">
      <title>Website PTI</title>
   </head>
   <body>
      <h1>Selamat Datang di Website PTI</h1>
      <p>Website ini berjalan menggunakan Apache Web Server.</p>
      <p>Domain: web.pti.test</p>
      <p>Server IP: 192.168.56.10</p>
   </body>
   </html>
   ```

   Simpan berkas tersebut.

4. Membuat konfigurasi virtual host

   Buat berkas konfigurasi:

   ```
   sudo nano /etc/apache2/sites-available/web.pti.test.conf
   ```

   Masukkan konfigurasi berikut:

   ```
   <VirtualHost *:80>
      ServerName web.pti.test
      DocumentRoot /var/www/web.pti.test/public_html

      <Directory /var/www/web.pti.test/public_html>
         Options -Indexes
         AllowOverride None
         Require all granted
      </Directory>

      ErrorLog ${APACHE_LOG_DIR}/web-error.log
      CustomLog ${APACHE_LOG_DIR}/web-access.log combined
   </VirtualHost>
   ```

   Penjelasan konfigurasi:

   | Parameter             | Fungsi                                                              |
   | --------------------- | ------------------------------------------------------------------- |
   | `VirtualHost *:80`    | Menentukan virtual host pada port 80                                |
   | `ServerName`          | Menentukan nama domain website                                      |
   | `DocumentRoot`        | Menentukan direktori utama website                                  |
   | `Options -Indexes`    | Mencegah penampilan daftar isi direktori                            |
   | `AllowOverride None`  | Menonaktifkan penggunaan aturan `.htaccess` pada direktori tersebut |
   | `Require all granted` | Mengizinkan permintaan akses terhadap direktori                     |
   | `ErrorLog`            | Menentukan lokasi log kesalahan                                     |
   | `CustomLog`           | Menentukan lokasi log aktivitas akses                               |

5. Mengaktifkan virtual host

   Jalankan:

   ```
   sudo a2ensite web.pti.test.conf
   ```

6. Memeriksa konfigurasi Apache

   ```
   sudo apache2ctl configtest
   ```

   Pastikan hasil pemeriksaan menunjukkan:

   ```
   Syntax OK
   ```

7. Memuat ulang konfigurasi Apache

   ```
   sudo systemctl reload apache2
   ```

   :::tip
   Jika terjadi masalah ketika menjalankan layanan Apache, gunakan perintah berikut untuk memeriksanya:

   ```
   sudo journalctl -u apache2 -n 50 --no-pager
   ```
   :::


8. Memeriksa daftar virtual host

   Jalankan:

   ```

   ```

   Periksa apakah kedua domain telah terdaftar sebagai virtual host pada port 80.

### 8.6. Pengujian Website dan Virtual Hosting (25 menit)

Pada tahap ini, mahasiswa akan melakukan pengujian untuk memastikan kedua website dapat diakses melalui nama domain masing-masing.

1. Menguji website pertama dari server

   Jalankan:

   ```
   curl http://web.pti.test
   ```

   Pastikan respons menampilkan konten website pertama.

2. Menguji website kedua dari server

   ```
   curl http://portal.pti.test
   ```

   Pastikan respons menampilkan konten website kedua.

3. Menguji berdasarkan alamat IP

   Jalankan:

   ```
   curl http://192.168.56.10
   ```

   Perhatikan bahwa permintaan langsung menggunakan alamat IP tidak secara otomatis memilih salah satu website berdasarkan nama domain. Apache dapat menampilkan virtual host default apabila permintaan tidak menyertakan hostname yang sesuai.

   Untuk menguji virtual host melalui alamat IP tetapi tetap menyertakan hostname, gunakan:

   ```
   curl -H "Host: web.pti.test" http://192.168.56.10
   ```

   Kemudian:

   ```
   curl -H "Host: portal.pti.test" http://192.168.56.10
   ```

   Periksa apakah masing-masing permintaan menampilkan konten website yang sesuai.

   :::tip
   Jika website tidak dapat diakses, periksa konektivitas jaringan, resolusi DNS, status Apache, konfigurasi virtual host, dan aturan firewall.
   
   Jika web tidak menampilkan hasil yang sesuai, periksa log kesalahan Apache:

   ```
   sudo tail -n 50 /var/log/apache2/error.log
   ```
   :::

4. Menguji dari komputer klien

   Pastikan komputer klien telah memperoleh konfigurasi jaringan dari DHCP dan menggunakan DNS server `192.168.56.10`.

   Buka browser pada komputer klien, kemudian akses:

   ```
   http://web.pti.test
   ```

   Selanjutnya akses:

   ```
   http://portal.pti.test
   ```

   Pastikan kedua website menampilkan halaman yang berbeda meskipun menggunakan alamat IP server yang sama.

5. Memeriksa log akses Apache

   Pada server, jalankan:

   ```
   sudo tail -f /var/log/apache2/web-access.log
   ```

   Buka website pertama dari komputer klien dan perhatikan apakah permintaan tercatat pada log.

   Lakukan pemeriksaan serupa untuk website kedua:

   ```
   sudo tail -f /var/log/apache2/portal-access.log
   ```

   Untuk menghentikan tampilan log secara langsung, tekan <kbd>Ctrl</kbd> + <kbd>C</kbd>.

### 8.7. Pemeriksaan dan Dokumentasi (15 menit)

## 9. Penugasan Praktikum

Mahasiswa diwajibkan menyelesaikan beberapa tugas berikut.

### 9.1. Tugas 1: Membuat Website Ketiga

1. Buat website baru dengan nama domain `lab.pti.test`.
2. Buat direktori website pada `/var/www/lab.pti.test/public_html`.
3. Buat halaman utama `index.html` dengan informasi nama website, deskripsi layanan, dan identitas server.
4. Atur permission direktori dan berkas website.
5. Dokumentasikan struktur direktori website.

### 9.2. Tugas 2: Konfigurasi DNS dan Virtual Host

1. Tambahkan DNS record `lab` pada zona `pti.test`.
2. Arahkan `lab.pti.test` ke alamat IP `192.168.56.10`.
3. Buat konfigurasi virtual host Apache untuk `lab.pti.test`.
4. Aktifkan konfigurasi virtual host.
5. Periksa konfigurasi menggunakan `apache2ctl configtest`.
6. Muat ulang layanan Apache.

### 9.3. Tugas 3: Pengujian Website

1. Uji resolusi DNS menggunakan `dig` atau `nslookup`.
2. Uji akses website menggunakan `curl`.
3. Akses website dari komputer klien melalui browser.
4. Pastikan website dapat diakses menggunakan nama domain.
5. Periksa log akses dan log kesalahan Apache.

### 9.4. Tugas 4: Analisis Virtual Hosting

Buat analisis singkat berdasarkan implementasi tiga website pada satu server. Analisis harus mencakup:

1. Perbedaan alamat IP dan nama domain dalam proses akses website.
2. Cara Apache membedakan permintaan untuk beberapa website.
3. Manfaat virtual hosting dalam pengelolaan server.
4. Risiko keamanan jika permission direktori website tidak dikonfigurasi dengan benar.
5. Perbedaan penggunaan Apache dan Nginx sebagai web server.
